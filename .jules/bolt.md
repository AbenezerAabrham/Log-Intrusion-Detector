## 2026-07-25 - [High-Performance Log Processing Optimizations]
**Learning:** Significant performance regressions can occur when calling dynamic object utilities such as `Object.entries(PATTERNS)` inside nested loops or executing array-filtering steps before iterations in JS/V8 engines. Creating intermediate filter/split arrays adds massive garbage collection pressure, particularly when parsing large server logs (e.g. 150k+ lines). Lazy initialization of mutable properties like `flaggedReasons`, caching object properties locally, hoisting constant regexes/patterns outside the hot paths, and using standard `for` loops completely avoids unnecessary allocations and leverages engine-level optimization paths.
**Action:** Always hoist regular expressions, map schemas, and patterns outside functions/loops, replace high-frequency `.forEach` and `.filter` with index-based `for` loops, cache deep object structure properties in local variables, and lazy-initialize intermediate arrays to optimize performance without sacrificing readability or functional correctness.
