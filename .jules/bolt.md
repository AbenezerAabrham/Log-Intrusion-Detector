## 2026-08-11 - Hoisting pattern entries and caching lookups in loop iterations
**Learning:** In hot execution paths such as `analyzeLogs` where each line of a potentially massive log file (100,000+ lines) is scanned, executing `Object.entries(PATTERNS)` inside the loop creates massive garbage collection pressure and CPU overhead by allocating a new array of entries on every single iteration. Hoisting this static pattern array outside of the function completely eliminates this O(N) allocation overhead. Additionally, converting high-level array iterations (`.forEach`, `.filter`) to sequential index-based `for` loops avoids function call stack overhead and intermediate array copies.
**Action:** Always identify static configurations and dictionary properties queried inside loops, and hoist their entry arrays, regular expressions, and other static objects outside the loop or function scope. Ensure intermediate arrays are avoided by tracking sizes and conditions inline.
