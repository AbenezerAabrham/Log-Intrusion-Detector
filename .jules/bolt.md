## 2026-08-14 - Hot Path Log Line Optimization Heuristics
**Learning:** High-volume string/log processing functions are highly sensitive to garbage collection overhead and object allocations inside sequential loops. Specifically, instantiating RegExp objects inside hot paths, splitting strings into intermediate filtered arrays, and performing frequent `Object.entries()` calls creates severe performance bottlenecks. Hoisting static variables, utilizing raw standard index `for` loops, pre-flattening object entries, and lazy-allocating list attributes dramatically improves execution speed (achieving ~38% execution time reduction).
**Action:** In client-side high-throughput applications, always hoist static variables/regexes outside function scopes, avoid intermediate array generation (e.g., using `filter` immediately after `split`), pre-calculate metadata structures, and lazy-initialize sub-arrays/objects only when they are strictly required.
