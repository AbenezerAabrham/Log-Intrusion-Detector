## 2026-07-30 - Log Intrusions Engine Optimization
**Learning:** Calling `Object.entries(OBJECT)` or `lines.forEach(...)` inside a high-frequency loop (like log line processing) creates unnecessary garbage collection pressure and CPU overhead. By hoisting static regular expressions and converting mapped entries to flattened data structures (`PATTERN_ENTRIES`) outside of the analysis loop, we eliminate runtime allocations. Furthermore, replacing intermediate filter-map arrays with a single-pass index-based standard `for` loop dramatically improves cache locality and performance on larger datasets.
**Action:** Hoist all static object conversions and regex definitions outside the tight iteration loops, and use sequential, index-based `for` loops rather than high-order array methods (`.forEach`, `.filter`, `.map`) when dealing with large performance-critical arrays.
