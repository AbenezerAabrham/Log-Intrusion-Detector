## 2026-08-10 - Optimizing Client-Side Log Scanning
**Learning:** Hoisting regular expressions (`IP_REGEX`, `STATUS_REGEX`) and pre-mapping `PATTERNS` to flat arrays of rules (`PATTERN_ENTRIES`) outside the main function scope completely avoids expensive re-allocations and lookups per execution. Eliminating intermediate `split().filter()` array allocations in favor of inline index-based loops and lazy-allocating localized arrays (like `flaggedReasons`) significantly minimizes garbage collection overhead in Node.js and client browsers.
**Action:** Always map complex objects to simple flat arrays/entries and hoist static objects/RegExes when running performance-sensitive iterations over large arrays of strings. Avoid array methods (`.forEach`, `.filter`, `.map`) in hot paths where standard `for` loops can process data in a single pass.
