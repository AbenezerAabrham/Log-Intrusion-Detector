## 2026-08-12 - Hoisting static regexes and pattern entries to avoid garbage collection and CPU overhead in tight loops
**Learning:** In hot functions running on 100,000+ items such as `analyzeLogs`, repeated extraction of static fields using `Object.entries(...)` and repeated instantiation of regular expressions introduces huge garbage collection overhead and redundant work. Caching IP statistics nested objects and replacing slower built-in methods (`parseInt`) with fast unary operator conversions (`+`) or replacing `.forEach` loops with sequential index-based `for` loops provides significant execution speedups.
**Action:** Always pre-evaluate and hoist static structures like regular expressions and Object entries/keys/values outside of tight processing loops, and use index-based `for` loops to process arrays with zero allocation overhead.
