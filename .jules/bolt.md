## 2026-08-09 - [Hoisting RegExes & Replacing .forEach Loops in Hot Paths]
**Learning:** In highly repetitive data parsing functions (like a log parser processing up to hundreds of thousands of lines), repeatedly compiling static regular expressions and creating array/object entry references in each execution loop introduces significant memory allocation and execution overhead. Additionally, using closure-based `.forEach` iterations results in massive function invocation overhead and prevents JIT from performing efficient loop unrolling or inline optimizations.
**Action:** Always hoist static regular expressions, regex definitions, and metadata entries (e.g., `Object.entries(...)`) out of hot functions. Replace closure-based iterators with sequential, index-based standard `for` loops, cache nested lookup paths, and use `else if` chains to skip redundant condition evaluation.
